# SKNet — instrucciones para agentes
Lee README y todos los docs antes de editar. Estos documentos y database/reference/schema.sql son la especificación acordada; si difieren del prototipo, prevalecen los docs actuales. El SQL es referencia no ejecutada, no garantía de diseño correcto: revisa y prueba migraciones. No inventes resultados, no declares pruebas aprobadas sin ejecutarlas. Documenta cambios y discrepancias en docs/IMPLEMENTATION_STATUS.md.
- Monolito modular FastAPI/Python + SQLAlchemy 2 + Alembic + PostgreSQL 17; React/TypeScript/Vite, Tailwind, shadcn personalizado, Lucide, Recharts. Docker Compose; cuatro servicios base frontend/backend/postgres/provisioner y un collector aislado por ISP con monitoreo. Sin Redis, Kubernetes, Next backend, Firebase, Supabase ni autenticación externa.
- DEV, TEST permanente, PROD; no STAGING. Nunca operar PROD, router real, infraestructura externa ni publicar Git sin autorización específica. Pruebas destructivas en BD temporal separada. No borrar volúmenes ni laboratorio anterior.
- Prioriza MVP vertical real. Implementa por etapas, ejecuta tests y registra evidencia, después continúa si se puede. No ampliar alcance por iniciativa propia. Si falta configuración externa, deja adaptador y prueba local, informa bloqueo; no falsifiques datos. No detener todo por una decisión menor reversible; explica supuestos.
- Seguridad desde inicio: aislamiento tenant, ámbitos SAAS/ISP, autorización API por permiso y plan, hashes, sesiones, auditoría, no secretos en git/logs/frontend. Nunca montar socket Docker salvo provisioner; collectors usan REST/token, no BD. No comandos shell con entradas de usuario.
- Prototipo v0 es referencia en references/v0-prototype/; inspecciona código y licencias, reutiliza diseño, elimina mocks del runtime real. No modificar referencia original. No generar pantallas falsas como funcionales.
- Migraciones Alembic son única vía de evolución; no ejecutar schema.sql además de migraciones. Validar DB nueva y actualización con datos. Seeds solo catálogo/permisos/plan trial sin credenciales; demo opcional explícita no PROD.
- Mantén README, pruebas y docs actualizados. No añadir secretos, .env reales, claves WG, dumps, node_modules, caches ni volúmenes al repositorio público. No realizar push ni desplegar sin solicitud.
