# Entornos y despliegue
DEV laptop/develop, TEST permanente Ubuntu GNS3/test (validación previa a PROD), PROD futuro/main. Sin STAGING. Cada entorno con 4 servicios base más collectors, DB PostgreSQL independiente, volúmenes, redes, secretos, usuarios, configuración y recursos VPN propios. Si host/router compartido: nombres Compose, puertos web, pools/puertos WG y etiquetas disjuntos; no colisiones. .env.dev/.env.test/.env.prod locales e ignorados; plantillas sin secretos. compose.yaml + compose.dev.yaml / compose.test.yaml / compose.prod.yaml; proyecto Compose explícito por entorno. TEST conserva datos, pruebas destructivas/automatizadas usan BD temporal aislada (no cuarto entorno permanente).
Git único; develop -> test -> main tras validar; no push automático. DEV recarga, TEST/PROD builds reproducibles y dependencias bloqueadas. Migraciones Alembic versionadas, prueba BD nueva y actualización existente, backup antes de TEST/PROD, restauración comprobada; aplicar antes de iniciar código incompatible, no borrar volúmenes. No copiar datos/secretos PROD a DEV/TEST. Semillas catálogo sin contraseñas; demo opt-in. PROD no ejecutar hasta autorización. Preconstruir imágenes y dependencias para demo offline; verificar red Docker Desktop en Windows y Linux Ubuntu. Documentar comandos concretos de build/migrate/start/backup/restore.
