# Arquitectura
Monorepo: backend/app (auth, platform, crm, billing, inventory, connectivity, monitoring, audit), frontend/src (auth, platform, enterprise, shared), monitoring/collector, provisioner/providers, database/reference, backend/migrations, infrastructure/templates/mikrotik, tests, docs, references/v0-prototype. Cuatro servicios base: frontend Vite compilado y servido localmente (proxy API mismo origen), backend FastAPI REST, PostgreSQL 17, provisioner Python Docker SDK + adaptador RouterOS. Desarrollo con bind mounts y reload. En producción HTTPS; DB sin exposición pública.
Collector Python Alpine con WireGuard, iproute2, iputils, NET_ADMIN/NET_RAW, sin privileged, red Docker propia /30, un túnel /31, token individual y volumen protegido. Backend gestiona jobs persistentes; provisioner reclama trabajos, reserva recursos de forma transaccional y reconcilia Docker/RouterOS. Provisioner único con socket Docker; nunca aceptar parámetros arbitrarios de contenedores. Collector no accede DB. REST /api/v1/collector/config, heartbeat, connectivity, results; API interna por gateway de red propia o ruta explícita verificada, firewall restringe host/otros collectors. El plano de gestión sigue alcanzable al caer WG. No conectar collectors a bridge común si rompe aislamiento. Router propio hace NAT UDP individual automatizada. Credenciales en secretos locales, no datos de otro ISP. Validar rutas y firewall antes de afirmar conectividad.
No microservicios innecesarios, Redis, broker, Kubernetes ni Java ahora. Posible proveedor Kubernetes y Java posterior. Separar lógica dominio, persistencia, API y adaptadores; servicios base independientes por entorno. Consultar ENVIRONMENTS.md.
